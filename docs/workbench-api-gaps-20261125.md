# 第一版资审工作台：接口缺口与实现边界

本轮只重构前端，不修改后端核心DTO、RoutingPolicy、身份守卫、操作授权、数据库或回写逻辑。

已核对用户ZIP的SHA256与仓库source-manifest.json一致，主表原始渠道为电话54、京麦14，共68。原始场景数与实际发布支持数必须分开。

| 缺口 | 现有接口与边界 | 前端处理及建议 |
| --- | --- | --- |
| 工作人员任务投影 | GET applications只有application_id/label/company_hint；SessionView无场景名、品牌、分类、提交次数、通话次数 | 显示“后端未提供”，不从编号、HTML或模型话术补造。建议独立的已鉴权工作人员只读任务列表/详情接口 |
| 核验前工作人员事实 | 现有快照统一隐藏reason/remedy/source_refs，缺少工作人员角色的独立事实视图 | 保留隐藏，不把同一内容放入商家对话。建议工作人员上下文接口与商家字幕分离，后台控制授权范围 |
| 完整渠道判定依据 | 路由决定和证据已存在数据库/SessionContext，但未暴露在SessionView | 显示服务端route，明确详细依据未开放；规则试算单列，不把试算写成当前任务判定 |
| 无副作用的队列加载 | 没有路由任务列表/会话列表；只能创建CASE_READY会话后取得实际route | 首次工作台加载为申请初始化可恢复的文本业务会话，不启动模型/语音/操作；缓存只保存会话ID，状态均重新读取后端。建议后续改用工作人员任务投影接口 |
| 京麦书面正文与执行 | 无已审written_text预览、受控execute入口；操作命令只能由Coordinator构造 | 保留书面卡和执行位置，禁用无接口操作，显示既有操作真实结果。不以发一条文本或改本地状态替代京麦执行 |
| 未接通事实入口 | HTTP层没有受控provider联系事件或工作人员模拟联系结果入口 | 不把挂断/静音/按钮点击当成no_answer；在开发设置用现有POST dev/routing核对后端分流，明确仅供规则试算 |
| 告知完成和回写 | 快照仅有record时能读到explanation_status；record存在不保证业务回写成功 | 未取得证据显示待确认；只有CLOSED与对应成功操作/record形成完成展示，挂断不计完成 |
| 发布支持范围 | 没有已发布场景目录接口，dev/routing可能只有synthetic规则样例 | 不把原始68或目录数量当支持数。显示实际加载任务数及发布支持目录待提供 |

建议后续独立后端PR提供工作人员任务投影、完整路由证据、已审书面预览与受控执行/联系事件接口；先明确鉴权和幂等/版本语义，经评审再接入。本轮不得为了填满卡片而拓宽SessionView或关闭身份/播放证据守卫。
