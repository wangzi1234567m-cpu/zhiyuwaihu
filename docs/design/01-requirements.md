# 需求与验收

赛事原有 ≥3 轮实时语音、P50≤2秒、打断、合规、闭环和 RSI 团队目标不变；测量仍以官方口径为准。11月22日校赛来自团队安排。新资料规定实际场景为 POP 商家资质审核驳回外呼，不是通用注册机器人。

| 来源 | 需求 | 验收 |
|---|---|---|
| 赛题数据说明及主表 | 既定审核结论→关单方式判定 | 使用申请单中的场景及事实，不让模型凭话术判断材料真伪 |
| 数据说明四段式 | 自报身份→核对公司／店铺→原因及整改→礼貌结束 | 核对前不说品牌、资质缺陷等详情；错人立即结束 |
| 主表关单原则 | 电话与京麦分流、重复提交、回电例外 | 判定函数可单测、包含证据引用和规则版本 |
| 高频QA | 解答操作路径和合理追问 | 每条具体业务说法有已审规则／QA依据；不承诺补交即通过 |
| 团队闭环 | 模拟驳回／预约／人工事件／结构化记录 | UI 显示真实工具状态；未知结果查证；无重复业务动作 |
| 团队范围 | 浏览器纯音频，AI主动开场 | 不向真实号码拨号，不连接真实京麦写接口 |
| 赛事＋团队 | 日志、归因、候选、回归、采纳／拒绝／回滚 | 实验固定数据、规则、代码和策略版本；没有提升就拒绝 |

校赛必做：主表全部有效记录结构化进入待审数据层；优先审核授权书缺项、授权过期、授权链不完整三个可整改场景；至少一条不强制外呼的京麦分支；商家拒绝、错人、预约回电、规则冲突、超时查证各有测试。导入68条不等于68条已支持自动回答，页面须列出支持范围。

后续增强：其余场景逐批审核发布、中文检索增强、噪声调参、真实沙箱适配。录音仅用于获准的合成测试，原始业务资料不公开上传。本次资料没有真实商家申请单和可调用业务接口，翟需制作明确标识为 synthetic 的申请单与 Mock。
