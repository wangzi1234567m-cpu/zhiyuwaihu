## Mock 的共同约定

Mock 使用与未来业务同一 BusinessPort，并复用 Quote／SubmissionResult／BusinessRecord 结构。第一版放在 FastAPI 进程内的独立模块，测试 harness 可以提供 dev-only HTTP wrapper；线上不暴露故障注入接口。前端 UI fixture 仅用于独立开发，不计作真实模块联调。

| fixture | 行为 | 必查断言 |
|---|---|---|
| success | 核验成功、可办套餐、提交成功、回写成功 | 订单引用当前报价与确认 |
| identity_fail | 错码／2 次上限 | 无敏感查询和订单 |
| query_fail | 明确可重试 503 后成功／持续失败 | 最多一次读重试，未生成假报价 |
| submit_reject | 明确业务拒绝、未受理 | 无订单；可由用户选择重新报价 |
| submit_timeout_before_dispatch | 在持久派发前取消／失败 | 零订单，operation cancelled/failed |
| submit_timeout_after_commit | Mock 已持久化订单但延迟响应 >3s | unknown→query→原订单；不产生第二单 |
| submit_unknown | 查询先 not_found_yet，后成功或一直未知 | 不自动重提；到期进入 manual_review |
| cancel_read | 查询等待中触发取消 | 不晚到覆盖当前报价 |
| cancel_submit | 派发前／后分别插话 | 前者零单，后者保留真实结果 |
| writeback_fail | 前两次失败，第三次成功 | 原订单不变，record revision 不重复 |
| stale_and_duplicate | 重放 ASR／事件／旧 generation／错 revision | 状态不回退、工具不重复执行 |

所有 fixture 使用固定逻辑时钟／可控延时和 seed；不通过字符串匹配测试问题硬编码模型答案。故障配置存 eval fixture 清单，不放 Prompt。测试数据库与演示库物理分开，reset 操作只允许测试环境。

## 每日联调与缺陷处理

每天建议 20:30 三人一起跑：正常链路→中断改方案→拒绝→超时查证。记录日期、代码 revision、契约／策略／数据版本、实际模块与 Stub 清单、session/trace、预期／实际、根因、负责人、修复 PR 和复测证据。至少一条使用真实模块连接；只看 Mock UI 不算。

定位顺序：浏览器音频／RTM → 云请求与绑定 → session/turn/generation → 状态机决策 → ToolGuard → operation/订单 → 回写。首层异常归王定位，明确归属后交模块负责人。P0 为越权／无确认下单／重复订单／隐私泄露／无法通话；当天修复并阻断发布。P1 为主要流程失败／无法恢复；P2 为非阻塞展示问题。

## PR 与持续集成

后续建仓库采用短分支、小 PR；不按人长期分叉出三套接口。公共契约改动须同时更新样例、Mock、前端生成类型和用例；王审查边界，相关负责人审查行为。业务／Prompt PR 说明触发条件、前后行为和实际验证，别只写“优化体验”。

必查：格式／静态类型、schema 重生成无漂移、正常／否定确认／改方案／越权用例、真实 DB 下并发幂等和崩溃恢复用例、SSE 分帧及晚到事件、秘密扫描、构建。纯文档编辑只校验链接／结构，不启动付费语音测试。涉及语音 adapter 的 PR 增加真实云三轮与取消证据；CI 不把所有 PR 都跑高成本语音全量。

部署拟用 Docker Compose＋单域名反向代理，提供 `docker compose up --build` 和显式 migration 命令；本轮尚无 Dockerfile／一键脚本，不能将设计命令描述成已经可运行。配置只由环境／secret 提供，`.env.example` 用占位符。启动健康检查至少覆盖 DB、模型配置、RTC 凭证配置；ready 不需要每次调用付费模型。

## 演示与交付

3 分钟演示建议：0:00 自报身份与核验；0:35 需求和报价；1:05 插话改方案；1:35 明确确认、提交和结果；2:10 看订单与结构化回写；2:30 展示已完成 RSI 实验的采纳／拒绝及回滚记录。若对话长，缩短解释和页面操作，不跳过核验与确认。另备完整 ≤5 分钟真实语音视频和故障用例证据。

交付包清单：源代码／锁文件／运行说明、技术方案、原始脱敏自测证据、RSI 前后对比、测试数据来源、版本及许可证表、演示视频。现场网络不可用时说明故障并按赛事安排处理；预录视频只能当备用材料，不能宣称是实时演示。
